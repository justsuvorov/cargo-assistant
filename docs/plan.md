## Тестовые данные

Корень `{ROOT}` = `D:\Projects\document-assistant\`. Это **реальные данные клиента**: читать для
анализа можно, в репозиторий — только обезличенные производные.

| Что | Путь |
|---|---|
| Формы ответа | `{ROOT}\Формы ответа\Структура проверки декларации.xlsx`, `…\Структура проверки декларации ПСГ.xlsx` |
| Декларации с разметкой ФСЦ | `{ROOT}\cargo tests\unpacked\{N}\` для N = 005, 35, 70, 76, 97, 107, 113, 114, 263, 271 |
| Без разметки | `{ROOT}\cargo tests\unpacked\{N}\` для N = 164, 274 |
| Упавшие в MVP | `…\unpacked\7\`, `…\unpacked\29\` (лог в .txt), `…\unpacked\46 …xlsx` (имя в cp866) |
| Сводка MVP против разметки | `{ROOT}\cargo tests\Сверка нового прогона с замечаниями ФСЦ.xlsx` |
| Декларация → папка полиса у заказчика | `{ROOT}\cargo tests\new_versions tests\files.txt` (в конце файла — лог MVP) |

В папке `unpacked\{N}\`: исходная декларация (.xls/.xlsx, имена вида «N — копия.xls»,
«N маршрут.xls» в cp866), «N – результат проверки.xlsx» (ответ MVP + колонка «Комментарии ФСЦ»),
скриншот экрана MVP. ГП и ДС локально нет (вопрос П-1).

## Карточки задач шага 2

### T-01 — каркас приложения

```
ID / требование:   T-01 → БТ-2 (очередь, прогресс), НФТ-В (время стадий)
Роль:              platform
Цель:              Приложение запускается в docker-compose, принимает файл, ставит задачу
                   reconcile в очередь, воркер проводит её по пустым стадиям с прогрессом.
Контекст:          CLAUDE.md; docs/architecture.md (стек, модель данных, очередь, хранилище,
                   интерфейс, конфигурация).
Контракты:         app/domain не используется напрямую; не менять.
Разрешённые файлы: app/core/, app/jobs/, app/web/, app/storage/, app/auth/, migrations/,
                   deploy/, Dockerfile, docker-compose.yml, pyproject.toml (зависимости),
                   tests/ для этих модулей.
Критерии приёмки:  - настройки только из переменных окружения (pydantic-settings), список из
                     docs/architecture.md; секретов в коде нет;
                   - логи на русском с job_id; время стадии сохраняется в Job;
                   - SQLAlchemy 2 async + Alembic: таблицы Policy, PolicyDocument, PolicyProfile,
                     Declaration, CheckResult, RuleSet, Job, EvalRun, LLMCall; первая миграция
                     применяется на SQLite и Postgres;
                   - очередь: атомарный захват (SKIP LOCKED / UPDATE … WHERE status='queued'),
                     WORKER_MAX_JOBS, возврат зависших по locked_at не больше
                     WORKER_MAX_ATTEMPTS раз, идемпотентность; тест на конкурентный захват
                     двумя воркерами без двойной обработки;
                   - хранилище: ключи из docs/architecture.md, тест на path traversal;
                   - вход: Keycloak OIDC и режим разработки без Keycloak (флаг окружения);
                   - страницы-заготовки: Полисы, Сверка (загрузка нескольких файлов, статус
                     задачи опрашивается HTMX), Архив; API загрузки и статуса;
                   - Dockerfile, docker-compose (api, worker, postgres); манифесты k8s
                     в deploy/ (api, worker, PVC, ingress, secret);
                   - все проверки из CLAUDE.md проходят.
Метрика:           не влияет на качество; время стадий пишется в Job.
Вне рамок:         разбор деклараций, проверки, LLM, отчёт xlsx, подтверждение профиля.
```

### T-02 — чтение и разбор деклараций

```
ID / требование:   T-02 → БТ-5 (форма, тип, номер), БТ-6 (RU/EN), НФТ-В (разбор < 1 с)
Роль:              parser
Цель:              Любая тестовая декларация превращается в Declaration с нормализованными
                   полями без LLM.
Контекст:          CLAUDE.md; docs/contracts.md (разделы 1–2); docs/declarations.md;
                   реальные декларации по путям из docs/plan.md (только чтение).
Контракты:         Declaration, Shipment, Field, Blank, Money/Amount, UnreadableError
                   из app/domain — не менять.
Разрешённые файлы: app/ingest/, app/declarations/, tests/ingest/, tests/declarations/,
                   pyproject.toml (зависимости xlrd, openpyxl, python-docx).
Критерии приёмки:  - ingest: .xlsx, .xls, .docx; .doc — через LibreOffice headless, если он
                     установлен, иначе понятная ошибка (решение по П-10 ещё не принято);
                   - выбирается лист с декларацией, лишние листы («Полис», «Счет на полис»)
                     игнорируются;
                   - форма vertical / psg определяется по структуре, колонки ПСГ — по подписям
                     RU и EN, а не по буквам;
                   - строки «ИТОГО» и строки без № п/п — не перевозки;
                   - номер декларации и нумерация «200» / «200/N» (источник номера — по
                     ответу на П-2; до ответа — из шапки, пазл на замену);
                   - нормализация дат, списков дат, сумм, валют, списков ТТН, пунктов маршрута
                     по таблице docs/contracts.md;
                   - таблица в отчёте: каждая реальная декларация → форма, число перевозок,
                     номер, число нераспознанных значений по полям;
                   - тест: разбор сгенерированной декларации на 61 строку < 1 с;
                   - фикстуры обезличены, есть EN-варианты подписей;
                   - все проверки из CLAUDE.md проходят.
Метрика:           доля распознанных значений по полям на реальных декларациях.
Вне рамок:         проверки и статусы, привязка к полису, промпты, отчёт xlsx.
```

### T-03 — эталон и прогон eval

```
ID / требование:   T-03 → НФТ-К, НФТ-В
Роль:              eval
Цель:              Черновой эталон из разметки ФСЦ и CLI, который прогоняет конвейер по
                   эталону и печатает точность по полям, время и число вызовов LLM.
Контекст:          CLAUDE.md; docs/requirements.md (методики); docs/contracts.md (GoldCase,
                   ключи полей); docs/questions.md; разметка ФСЦ по путям из docs/plan.md.
Контракты:         GoldCase/Expectation, Verdict, Place/Spot, Status из app/domain — не менять.
Разрешённые файлы: tools/eval/, docs/eval/, tests/gold/ (формат и загрузчик), tests/tools/eval/.
Критерии приёмки:  - формат эталона: декларация, строка, ключ поля, ожидаемый статус,
                     источник (ФСЦ «верно» / пояснение ФСЦ), заметка; файлы обезличены;
                   - скрипт обезличивания (названия, ИНН, номера ГП, адреса, ФИО →
                     согласованные заглушки); исходники не попадают в git;
                   - черновой эталон по правилу: «верно» → статус MVP; пояснение → статус по
                     пояснению; неясно → в docs/eval/questions.md, а не в эталон;
                   - соответствие подписей полей MVP ключам полей из docs/contracts.md;
                   - CLI прогоняет пустой конвейер (заглушка, все поля «требует проверки»)
                     и даёт отчёт: точность по полям, доля «требует проверки», время на
                     декларацию, число вызовов LLM;
                   - сравнение только с эталоном, не с прошлым прогоном;
                   - все проверки из CLAUDE.md проходят.
Метрика:           отчёт пустого конвейера как нулевая точка.
Вне рамок:         продуктовый код в app/, изменение ожидаемых статусов без пользователя.
```
