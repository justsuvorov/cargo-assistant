# Eval

Прогон конвейера по эталону и отчёт по методикам НФТ-К и НФТ-В
([requirements.md](../requirements.md)). Формат эталона — [tests/gold/README.md](../../tests/gold/README.md),
требования к эталону — [gold-requirements.md](gold-requirements.md).

## Команды

```
python -m tools.eval run [--part dev|holdout|all] [--pipeline stub|match|parsed|checked] [--real каталог]
                         [--gold tests/gold/cases] [--manifest tests/gold/manifest.yaml] [--cards cards]
                         [--standalone поле,поле,…] [--out файл.md]
python -m tools.eval template <файл декларации> [--out каталог] [--cards cards]
python -m tools.eval load <каталог с заполненными шаблонами> [--gold tests/gold/cases] [--glossary …]
python -m tools.eval split [--real каталог] [--share 0.3]
python -m tools.eval gold --source "<папка unpacked>" [--glossary data/real/glossary.txt]
python -m tools.eval mask <исходный.txt> <обезличенный.txt> [--glossary data/real/glossary.txt]
```

- `run` — прогоняет конвейер по декларациям выбранной части эталона и печатает отчёт. По умолчанию
  считается только рабочая часть `dev`; контрольная `holdout` — флагом `--part holdout` (её
  запускает оркестратор при приёмке этапа), `--part all` — обе части. Конвейеры:
  - `stub` — пустой конвейер, во всех местах эталона «требует проверки» (нулевая точка);
  - `match` — контрольная заглушка, везде «совпадает» (сколько даёт тривиальный ответ);
  - `parsed` — настоящий разбор: файл декларации читается через `app.declarations`, каждая
    перевозка получает ответ-заглушку «требует проверки» в каждом поле своей формы (D-14).
    Отчёт показывает, какие места эталона нашлись в разборе, а какие нет, и время разбора.
  - `checked` — настоящий конвейер этапа 1: разбор `app.declarations`, затем каждая карточка
    `--cards` (`app.rules.cards.Cards`) проверяет своё поле с полисом `Vacant` (номер ГП из
    шапки, профиля ещё нет — пункты полиса отсутствуют, `clause.absent`). Смысловые вопросы
    получает заглушка `tools.eval.semantics.Doubt`: «требует проверки» с кодом `eval.semantic`,
    каждая пачка вопросов — один вызов LLM в отчёте; модель и сеть не используются. Декларация
    читается один раз и хранится в `Kept`, время делится на стадии «разбор» и «проверки».
    Сбой разбора или проверок одной декларации попадает в причины сбоя отчёта, прогон идёт
    дальше.

  `--standalone` — поля, которые без профиля полиса решаются сами; их точность выводится
  отдельным разделом в конце отчёта (по умолчанию packaging, sealing, other, beneficiary,
  document, document_date, document_number, transshipment, carrier).
- `template` — читает декларацию через `app.declarations` и пишет шаблон разметки для ФСЦ
  `<номер> – разметка.xlsx` (раздел 3 требований к эталону). Пример по вымышленной декларации —
  [example/](example/).
- `load` — проверяет заполненные шаблоны и пишет обезличенные CSV эталона через маску. Ошибки
  выводятся списком «файл, строка: что не так»; пока они есть, эталон не пишется. Декларацию,
  которая уже есть в эталоне, `load` не перезаписывает (правило 8).
- `split` — делит декларации эталона на `dev` и `holdout` и записывает деление в манифест.
- `gold` — собирает черновой эталон из разметки ФСЦ ответов MVP: `tests/gold/cases/*.csv`,
  [questions.md](questions.md), [summary.md](summary.md).
- `mask` — обезличивает текстовый файл.

Каталог реальных деклараций для `parsed` и `split` — `--real`, иначе переменная окружения
`EVAL_REAL_DIR`, иначе `data/real/`. Файлы ищутся во всех подкаталогах (xls, xlsx, xlsm, doc,
docx; без «результат проверки» и «разметка») и сопоставляются по номеру из шапки декларации
(D-21). Без каталога команда завершается с понятной ошибкой.

## Номера (D-30)

Номер декларации — только идентификатор. Eval сравнивает номера по цифрам без ведущих нулей:
«70» = «070» = «р-070», «005» = «5»; номер строки «N/k» — так же по каждой части («070/03» =
«70/3»). Эталон не переименовывается.

## Шаблон разметки

Лист «Разметка» — форма ответа: строка на каждую перевозку и каждое поле формы декларации (набор
и порядок полей — из `forms` карточек, D-14; нумерация «200» или «200/N»). Колонки:

| Колонка | Кто заполняет | Что в ней |
|---|---|---|
| Номер декларации/строки | шаблон | «200» или «200/N» |
| Наименование поля | шаблон | подпись из формы ответа |
| Значение в декларации | шаблон | как его прочитала система, для справки и проверки правила 3 |
| Ожидаемый статус | эксперт | выпадающий список: совпадает / не совпадает / требует проверки |
| Пункт ГП / ДС | эксперт | обязателен для «не совпадает» |
| Причина | эксперт | обязательна для «не совпадает» и «требует проверки» |
| Уверенность | эксперт | выпадающий список: уверен / спорно |
| Примечание | эксперт | необязательно |

Лист «Инструкция» — правила раздела 3 коротко и ячейка для времени разметки.

Проверки `load`: статус из трёх; для «не совпадает» есть пункт и причина; для «требует
проверки» есть причина; уверенность указана; одно место не размечено дважды; одинаковые
непустые значения поля в одной декларации у строк «уверен» получили один статус (иначе —
сообщение о расхождении). Строки «спорно» пишутся в эталон, но в расчёт точности не входят.

## Версии и деление

Манифест [tests/gold/manifest.yaml](../../tests/gold/manifest.yaml): версия эталона, журнал
изменений (что, почему, кем подтверждено) и для каждой декларации — группа полиса и часть.

- Группа полиса — порядковая метка «Полис-N», номер полиса в git не попадает.
- Декларации одного полиса — в одной части; манифест с нарушением не читается.
- `split` сохраняет уже назначенные части; новая группа получает часть известной декларации
  своего полиса, иначе идёт в `holdout`, пока контрольная часть не превышает 30% деклараций,
  в фиксированном псевдослучайном порядке.
- Версия эталона меняется вместе с ожидаемыми статусами и записью в журнале, только с согласия
  пользователя.

## Отчёт

- Единица — строка «поле × перевозка»; сравнение только с эталоном, не с прошлым прогоном.
- В шапке — версия эталона и часть; в расчёт идут строки «уверен», число спорных показано отдельно.
- Верно — статус ответа совпал с ожидаемым; «требует проверки» засчитывается, только если эталон
  его ожидает.
- По каждому полю: случаев, верно, точность, доля ответов «требует проверки», нет ответа и для
  каждого статуса «найдено из ожидаемых» и «лишних» (диагностика, методика не меняется, D-25).
- По ожидаемому статусу: какая доля «совпадает», «не совпадает», «требует проверки» найдена.
- Матрица статусов по полям: для каждого поля и ожидаемого статуса — сколько ответов
  «совпадает», «не совпадает», «требует проверки» и сколько мест без ответа.
- Коды причин по полям: код причины первого ответа в месте эталона, сколько таких ответов и
  сколько из них верны (отличает «нет полиса», `clause.absent`, от решения правила).
- По декларации: точность, время `reconcile`, число вызовов LLM и время стадий, если конвейер
  их меряет; среднее и максимальное время, в том числе по каждой стадии; всего и максимум
  вызовов; число ответов вне эталона.
- «Места эталона и ответа»: по каждой декларации — причины сбоя (файл не найден, не прочитан,
  сбой проверок), места эталона без ответа и ответы вне эталона.
- Последний раздел — точность полей `--standalone` отдельно.

## Подключение конвейера

Конвейер подключается через `tools.eval.pipeline.Pipeline`:

```python
class Pipeline(Protocol):
    def reconcile(self, declaration: str) -> Outcome: ...   # Outcome: verdicts(), calls(), faults(), stages()
```

Конвейер получает только номер декларации — эталон ему недоступен. Время измеряет eval вокруг
`reconcile`, вызовы LLM сообщает конвейер (счётчик `FakeModel` или журнал `LLMCall`). Сбой на
декларации конвейер возвращает в `faults()`, а не исключением: отчёт показывает причину.

## Обезличивание

`tools.eval.mask.Anonymity` заменяет номера ГП, ИНН, организации с ОПФ (в том числе вложенные
кавычки и иностранные LLC / Co., Ltd), ФИО с инициалами, адреса с улицей и домом, почту и
слова из глоссария на заглушки `ГП-1`, `ИНН-1`, `Организация-1`, `Лицо-1`, `Адрес-1`,
`Почта-1`, `Название-1`. Номер заглушки согласован в пределах корпуса: один фрагмент — одна
заглушка. Глоссарий (названия без ОПФ, улицы без слова «ул.») лежит вне git, в
`data/real/glossary.txt`. Сборка эталона (`gold`, `load`) пропускает через маску все ячейки,
которые пишет. Результат проверяет пользователь (D-10).
