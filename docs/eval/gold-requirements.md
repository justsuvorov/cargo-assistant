# Требования к эталонному набору (golden dataset)

Статус: **отправлено в ФСЦ 31.10.2026, ждём ответа.**

Эталон — это декларации с полным пакетом полиса и с ответом, который эксперт ФСЦ считает
правильным для каждой строки «перевозка × поле». По эталону проверяются требования к
качеству (НФТ-К, 90%) и времени (НФТ-В, 30 с), а также любые изменения правил, промптов,
парсера и профиля полиса (правило 9).

## 1. Почему текущего черновика мало

Сейчас в черновике 232 строки по 11 декларациям. Их хватает, чтобы начать работу, но не чтобы
принимать этапы:

| Проблема | Что видно в черновике |
|---|---|
| Разметка оценивала ответ MVP, а не задавала правильный ответ | 93 строки из 328 не удалось однозначно перевести в ожидаемый статус |
| Мало расхождений | «не совпадает» — 18 строк (7,8%); ответ «всё совпадает» набирает 91,4% |
| Почти нет «требует проверки» | 2 строки; нельзя проверить, что система честно отдаёт спорное человеку |
| Нет полисов | без ГП и ДС нельзя проверить сроки, лимиты, исключения и редакции |
| Узкий охват | 11 деклараций, около 8 полисов, нет английских деклараций, нет .doc |

## 2. Состав набора

### Объём

| Показатель | Минимум для приёмки этапа 3 | Цель |
|---|---|---|
| Деклараций | 40 | 100 |
| Строк «перевозка × поле» | 1 000 | 3 000 |
| Разных генеральных полисов | 15 | 30 |
| Строк на каждое поле | 50 | 150 |
| Строк «не совпадает», всего | 15% от строк | 20% |
| Строк «не совпадает» на каждое поле, где расхождение возможно | 10 | 30 |
| Строк «требует проверки» | 30 | 100 |

Почему так: при 50 строках на поле точность 90% измеряется с погрешностью около ±8%,
при 150 — около ±5%. Без заметной доли расхождений точность не отличает рабочую систему от
ответа «всё совпадает».

### Охват

| Что | Требование |
|---|---|
| Формы | вертикальная и ПСГ — не меньше 40% набора каждая |
| Число перевозок | однострочные, мультистрочные; не меньше 3 деклараций на 50+ перевозок (для НФТ-В) |
| Форматы файлов | .xls, .xlsx; .doc и .docx, если они встречаются у клиентов |
| Язык | не меньше 10% деклараций на английском и несколько двуязычных (D-27) |
| Период | декларации разных месяцев; перевозки до и после вступления ДС в силу |
| Валюта | суммы в рублях и не меньше 5 деклараций в другой валюте |

### Пакеты полисов

Каждая декларация в наборе приходит с полным пакетом своего полиса: текст ГП, все ДС, особые
условия клиента, строка из общего файла особых условий, перечень перевозчиков. Среди полисов
должны быть:

- ДС, меняющее срок действия (продление);
- ДС, меняющее лимит;
- ДС, заключённое к конкретной декларации или отгрузке;
- несколько ДС к одному пункту с разными датами вступления;
- ДС в формате .doc;
- ГП с риском, требующим сверки перевозчиков (например 3.4.28), и без него;
- ГП с условием продления до окончания ответственности по партии и без него;
- ГП с особыми условиями, меняющими правило поля (как «в соответствии с п.8 ГП»).

### Трудные случаи

Каждый случай — не меньше 3 строк в наборе. Список составлен по замечаниям ФСЦ к MVP.

| Поле | Случай |
|---|---|
| Страхователь | сокращение («ТД» = «Торговый дом»), регистр, кавычки; действительно другой страхователь |
| № ГП | верный номер; чужой номер; неверная дата ГП |
| Период | внутри срока; начало вне срока; окончание за сроком при условии продления и без него; окончание раньше начала; опечатка в годе |
| Груз | разрешённый груз; груз из исключений (мех, почтовые отправления); несколько позиций, одна из них в исключениях; категорию нельзя определить по названию (скоропортящийся?); «в соответствии с п.5 ГП» |
| Выгодоприобретатель | заполнен; пусто; «нет»; без ОПФ; иностранная ОПФ |
| Страховая сумма | ниже лимита; ровно лимит; выше лимита; лимит изменён ДС; ДС к другой декларации; другая валюта |
| Транспорт | «авто»; марка машины без слова «авто»; смешанная перевозка; «авто с перегрузом на границе»; вид, которого нет в ГП; ссылка на пункт ГП |
| Маршрут | полный адрес; только город или терминал; опечатки; исключённая территория; несколько пунктов через тире; одинаковый адрес в разных строках; пусто |
| Пункт перегрузки | пусто при несмешанной перевозке; пусто при смешанной; заполнен; «по решению перевозчика» |
| ТТН | один номер; список номеров; список дат без года; пусто |
| Перевозчик (вертикальная) | заполнен с ОПФ; без ОПФ; пусто; есть в перечне и нет в перечне при риске |
| Пломбирование, прочие сведения | пусто; заполнено |

## 3. Что эксперт размечает

Главное отличие от прошлой разметки: **эксперт записывает правильный ответ сам, не глядя на
ответ системы.** Оценка «верно / неверно» чужого ответа в эталон не годится.

Для каждой перевозки и каждого поля своей формы (вертикальная — 15 полей, ПСГ — 13, D-14):

| Колонка | Обязательно | Содержание |
|---|---|---|
| Номер декларации/строки | да | «200» или «200/N», как в форме ответа |
| Наименование поля | да | подпись из формы ответа |
| Ожидаемый статус | да | совпадает / не совпадает / требует проверки |
| Пункт ГП / ДС | да для «не совпадает» | например «п. 12 ГП», «п. 1 ДС 4» |
| Причина | да для «не совпадает» и «требует проверки» | одно предложение: что именно не так или чего не хватает |
| Уверенность | да | уверен / спорно |
| Примечание | нет | всё, что поможет понять решение |

Правила разметки:
1. «Требует проверки» ставится, только если по документам пакета без дополнительных сведений
   решить нельзя. Причина обязательна.
2. Если правило сверки неясно — пометка «спорно» и вопрос, а не догадка. Спорные строки не
   входят в расчёт точности, пока их не разрешат.
3. Одинаковое значение в разных строках одной декларации получает одинаковый ответ.
4. Решения, которые уже приняты (журнал D-xx), соблюдаются; например, сумма в другой валюте —
   «требует проверки» (D-22).
5. Шаблон — Excel по форме ответа с колонками выше, один файл на декларацию. Шаблон готовит
   агент `eval`.

## 4. Контроль качества разметки

- **Двойная разметка.** Не меньше 20% деклараций размечают два эксперта независимо.
  Считается доля совпавших статусов. Расхождения разбирает старший эксперт.
- **Порог согласия.** Если эксперты совпадают меньше чем в 95% строк, сначала уточняются
  правила (карточки), потом продолжается разметка. Если согласие экспертов ниже 90%, цель
  НФТ-К в 90% недостижима и её нужно обсуждать с заказчиком.
- **Время разметки** записывается на каждую декларацию: это база для оценки пользы системы.

## 5. Разделение набора

| Часть | Доля | Кто видит | Зачем |
|---|---|---|---|
| Рабочая (dev) | 70% | разработчики и агенты | настройка карточек, промптов, парсера |
| Контрольная (holdout) | 30% | только прогон eval при приёмке этапа | честная оценка без подгонки под эталон |

Декларации одного полиса попадают в одну часть, иначе контрольная часть подсказывает правила
полиса. Агенты не открывают контрольные файлы; прогон по ним запускает оркестратор при приёмке.

## 6. Данные и хранение

- Исходные декларации и пакеты полисов остаются в контуре: каталог `data/real/` вне git.
- В git попадают только обезличенные CSV эталона: без названий, ИНН, номеров полисов,
  адресов и ФИО. Обезличивание делает скрипт `python -m tools.eval mask`, список названий без
  ОПФ — `data/real/glossary.txt`. Результат проверяет пользователь (D-10).
- Внешним моделям (Anthropic, Gemini) эталон с реальными данными не передаётся (П-17); прогон
  по реальным документам — только через шлюз ВСК.

## 7. Версии и изменения

- У эталона есть версия (v1, v2, …) и журнал изменений: что изменено, почему, кем
  подтверждено.
- Ожидаемый статус меняется только с согласия пользователя (правило 8). Исправление эталона
  «под систему» запрещено.
- Каждый отчёт eval указывает версию эталона, версию карточек и коммит кода.

## 8. Что считает отчёт

По всему набору и отдельно по каждому полю, форме и языку:
- точность — доля строк, где статус совпал с эталоном (методика НФТ-К, D-4; пока без
  изменений, D-25);
- для каждого статуса — сколько найдено из ожидаемых и сколько найдено лишних (особенно
  «не совпадает»);
- доля ответов «требует проверки» (цель ≤ 10%);
- время на декларацию (среднее, максимум, на крупных декларациях) и число вызовов модели.
