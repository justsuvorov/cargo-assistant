# Журнал решений

Статусы: **принято** (пользователем), **принято по умолчанию** (действует, пока пользователь не
изменит), **предложено** (ждёт пользователя или заказчика), **отклонено**.

| ID | Решение | Статус |
|---|---|---|
| D-1 | Сетевого каталога нет, все файлы хранятся в системе. Месячная папка «Декларации/{месяц}» из БТ-5 становится полем «месяц» (по дате начала периода страхования) с фильтром; результат скачивается по одному файлу или архивом | принято пользователем |
| D-2 | База знаний «компилируется» в карточки правил по полям (БТ-3a, БТ-4). Бизнес правит базу знаний; система разбирает её на карточки; админ подтверждает; новая версия применяется без перезапуска. Свободный текст базы целиком в промпт не попадает | предложено, на согласовании с заказчиком |
| D-3 | Третий статус «требует проверки» с причиной, в дополнение к «совпадает / не совпадает» | предложено, на согласовании с заказчиком |
| D-4 | Методика НФТ-К — см. [requirements.md](requirements.md) | предложено, на согласовании с заказчиком |
| D-5 | Методика НФТ-В — 30 с при подтверждённом профиле; профиль строится в фоне один раз | предложено, на согласовании с заказчиком |
| D-6 | Приёмка задач — оркестратор; приёмка этапов — пользователь | принято по умолчанию |
| D-7 | Отдельного агента-ревьюера нет: ревью делают `eval` и оркестратор | принято по умолчанию |
| D-8 | Модели по ролям: platform, parser — sonnet; rules, llm, eval — opus | принято по умолчанию |
| D-9 | Субагенты могут читать реальные документы для отладки, но не копировать их в репозиторий | принято по умолчанию |
| D-10 | Обезличивание эталона — скрипт агента `eval`, результат проверяет пользователь | принято по умолчанию |
| D-11 | Полисы и декларации видны всей группе ФСЦ (группа Keycloak); подтверждение профиля и базы знаний — по ролям | принято по умолчанию |
| D-12 | Привязка декларации к полису — автоматически по «№ ГП», с подтверждением в интерфейсе при неоднозначности | принято по умолчанию |
| D-13 | Применение требований к коду к Python — раздел «Требования к коду» в [CLAUDE.md](../CLAUDE.md) | предложено пользователю |
| D-14 | Набор строк результата определяется **формой** декларации (вертикальная — 15 полей, ПСГ — 13), а нумерация «200» или «200/N» — **числом перевозок**. Основание: декл. 35 — ПСГ с одной перевозкой; MVP вывел вертикальные поля, ФСЦ: «поле отсутствует в декл.» | принято пользователем |
| D-15 | Карточка проверяет всю декларацию сразу (`Card.verdicts(declaration, policy)`), чтобы смысловые вопросы шли одним пакетом и одинаковые значения получали одинаковый результат | предложено пользователю |
| D-16 | Пункт полиса хранится списком редакций с `scope` — «все декларации» или список номеров. ДС к конкретной декларации не применяется к другим (замечания ФСЦ по 76, 97, 107) | предложено пользователю |
| D-17 | Особые условия клиента, меняющие правило поля, хранятся в профиле как пункт `accepted.<поле>` и проверяются движком до основной проверки (декл. 263) | предложено, нужно подтверждение ФСЦ |
| D-18 | Правила ruff RUF001–RUF003 (похожие кириллические буквы) отключены: русский — язык сообщений проекта. FBT003 отключено в тестах: `equal_to(True)` — обычный вызов Hamcrest. Исключения называются с суффиксом Error (требование ruff N818) | принято по умолчанию |
| D-19 | Собственные правила стиля проверяет `python -m tools.lint` (см. [code-style.md](code-style.md)) | принято по умолчанию |
| D-20 | Работаем с git по старой схеме: без GitHub issues, `gh` и скиллов `courier:*`, `bugscribe:*`. Ветка на задачу (`t-01`, `t-02`…) от `develop`, после приёмки оркестратором — слияние в `develop`. Коммиты — обычным `git`; `git push` — только с разрешения пользователя | принято пользователем |
| D-21 | Номер декларации берётся из шапки декларации, а не из имени файла | принято пользователем |
| D-22 | Страховая сумма в валюте, отличной от валюты лимита, не пересчитывается и не сравнивается; ответ даётся в валюте декларации, статус — «требует проверки» | принято пользователем |
| D-23 | Декл. 97: сумма 920 000 000 при лимите 900 000 000 — «не совпадает». Отметка ФСЦ «верно, но комментарий "совпадает"» — ошибка разметки; в эталоне ожидается «не совпадает» | принято пользователем |
| D-24 | История git переписана: из всех коммитов убраны названия клиентов и номера полисов (локально выполнено; принудительный push в `origin/main` делает пользователь) | принято пользователем |
| D-25 | Методика НФТ-К пока без изменений, хотя ответ «всё совпадает» набирает на черновом эталоне 91,4% (находка T-03) | принято пользователем |
| D-26 | Из номера декларации в шапке убирается буквенный префикс: «Р-005» → «005» | принято пользователем |
| D-27 | Декларации бывают на английском, текст ГП — всегда на русском. Английские значения распознаются, переводятся на русский и сравниваются с ГП; результат и комментарии — на русском | принято пользователем |
| D-28 | Строки «Перевозчик» в результате ПСГ-формы нет (Ф-14) | принято пользователем |
| D-29 | Клиент модели — по образцу класса пользователя для шлюза ВСК; для разработки можно выбрать Anthropic или Gemini через переменные окружения | принято пользователем; ограничение по данным — П-17 |
| D-30 | Номер декларации — только идентификатор: форматы «050», «р 050», «р-050» сводятся к цифрам с первой цифры. Эталон не переименовывается; eval сопоставляет номера по цифрам без ведущих нулей («70» = «070»). Формат имени файла результата вторичен | принято пользователем |
| D-31 | Файлы .doc читаются через LibreOffice headless: 23 реальных .doc пилота ФСЦ прочитаны без ошибок, 1,2–2,2 с на файл, первый запуск 14 с. Word не подходит: в проде Linux-контейнер | принято пользователем |
| D-32 | Пакет полиса на диске: файлы ГП лежат прямо в папке полиса, все ДС — в папке «ДС» (внутри могут быть подпапки); подпапка «ГП» тоже допустима. Вид документа и номер ДС определяются по содержимому, а не по имени файла | принято пользователем |
| D-33 | Выбор редакции: ДС к конкретной декларации применяется только к ней и важнее общих; среди общих — последняя по дате вступления, при равенстве — по номеру ДС. Общее ДС действует до замены пункта следующей редакцией, срок полиса проверяется отдельно. Сам ГП действует на любую дату, поэтому перевозка вне срока получает «не совпадает», а не «пункт не найден». Редакция заменяет только свой подпункт и вложенные в него: ДС на 12.7 не отменяет 12.5 | предложено, вопрос Ф-25 |
| D-34 | Мониторинг: журнал проверок деклараций, попыток, воркеров и вызовов модели — в таблицах Postgres, хранение 3 месяца; метрики — представления `v_*` в схеме `monitoring`; алерты — представление `v_alerts` с порогами внутри, Superset шлёт письма по запросам к нему. Мы создаём только таблицы и представления; дашборд, рассылку и права настраивает пользователь. Очистка через 3 месяца касается журнала; задачи, декларации и результаты хранятся дольше, и графики исходов и использования видят всю их историю. Время в журнале и представлениях — в UTC, сдвиг на московское делается в Superset (Hours offset датасета); в представлениях с разбивкой по дням сутки режутся по UTC. Пороги стартовые, пересмотр через две недели работы. В журнале и представлениях нет данных клиента: только идентификаторы, коды, счётчики и время | принято пользователем |
| D-35 | Дата окончания перевозки раньше даты начала — «не совпадает» с комментарием «Дата окончания раньше даты начала». Порядок дат проверяется кодом до сверки со сроком ГП и не требует профиля полиса; статус задаёт карточка | ответ на Ф-3 взят из разметки ФСЦ: декларация 97, период — «верно» на «не совпадает» (эталон, basis fsc-ok) |
