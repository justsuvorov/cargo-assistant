# Доменные контракты

Код — в [app/domain/](../app/domain/). Меняет только оркестратор. Статус документа:
**предложено, на подтверждении пользователя**.

## 1. Карта интерфейсов

```
Declaration ── shipments() ──► Shipment ── field(key) ──► Field (Fact)
                                   │                        └─ Blank — пустое или отсутствующее поле
                                   └─ start() → дата начала перевозки
Policy ── clause(key, shipment) ──► Clause (Fact)            ◄── Revision.clause()
   │                                 └─ Absent — пункта нет в профиле
   └─ conditions() → особые условия для вывода в результат (БТ-3b)
Card ── verdicts(declaration, policy) ──► Verdict*
                                           ├─ place()  → Place  (строка «200/1» × ключ поля)
                                           ├─ status() → Status (Match | Mismatch | Review)
                                           ├─ reason() → Reason (код, источник rule|llm)
                                           └─ remark() → Remark (комментарий, ссылка на пункт)
Semantics ── verdicts(questions) ──► Verdict*      (Question = место, значение, пункт, правило)
GoldCase ── agrees(verdict) ──► bool
```

| Интерфейс | Методы | Реализации в домене | Кто реализует остальное |
|---|---|---|---|
| `Status` | `key()`, `text()` | `Match`, `Mismatch`, `Review` | — |
| `Reason` | `code()`, `source()` | `Cause` | — |
| `Money` | `exceeds(other)`, `under(value, currency)`, `text()` | `Amount` | — |
| `Fact` | `text()`, `dates()`, `amounts()`, `entries()` | — | общая часть `Field` и `Clause` |
| `Field` | `Fact` + `key()`, `filled()` | `Blank` | `declarations/` |
| `Clause` | `Fact` + `reference()` | `Absent` | `policy/` |
| `Place` | `shipment()`, `field()`, `same(other)` | `Spot` | — |
| `Remark` | `comment()`, `reference()` | `Note` | — |
| `Verdict` | `place()`, `status()`, `reason()`, `remark()` | `Ruling` | — |
| `Shipment` | `number()`, `declaration()`, `field(key)`, `start()` | — | `declarations/` |
| `Declaration` | `number()`, `form()`, `policy()`, `shipments()` | — | `declarations/` |
| `Revision` | `governs(shipment)`, `supersedes(other)`, `clause()` | — | `policy/` |
| `Policy` | `number()`, `clause(key, shipment)`, `conditions()` | — | `policy/` |
| `Card` | `field()`, `covers(form)`, `title(form)`, `subject()`, `verdicts(declaration, policy)` | — | `rules/` |
| `Question` | `place()`, `value()`, `clause()`, `rule()` | `Inquiry` | — |
| `Semantics` | `verdicts(questions)` | — | `semantic/`; в тестах fake |
| `GoldCase` | `place()`, `agrees(verdict)` | `Expectation` | — |

Ошибки домена: `UnreadableError` (значение нельзя прочитать, например нет даты начала у
`Shipment.start()`), `IncomparableError` (суммы в разных валютах без курса). Карточка
превращает их в «требует проверки» с кодом причины; молча они не глотаются.

### Почему так

- **Карточка обрабатывает всю декларацию, а не одну строку.** Так смысловая карточка задаёт
  все вопросы одним пакетом, одинаковые значения спрашиваются один раз и получают одинаковый
  результат (правило 6, замечание ФСЦ по 114/1 и 114/2).
- **Поле и пункт полиса — оба `Fact`.** Проверки сравнивают одно с другим одинаковыми
  средствами: даты с датами, суммы с суммами, позиции с позициями.
- **`Policy.clause(key, shipment)` получает перевозку.** Профиль сам выбирает редакцию по дате
  начала перевозки и по тому, к какой декларации относится ДС (правило 5, замечания ФСЦ по
  76, 97, 107).
- **Пустое — это объект.** `Blank` и `Absent` вместо `None`.

## 2. Ключи полей

Ключ поля — общий для парсера, карточек, результата и эталона.

| Ключ | Вертикальная форма | ПСГ | Что возвращает `entries()` |
|---|---|---|---|
| `insurer` | Страхователь | Страхователь | одно значение |
| `policy` | № ГП и дата | № ГП и дата | одно значение; `dates()` — дата ГП |
| `cargo` | Полное наименование груза | Наименование груза | позиции через запятую, «;», перевод строки |
| `packaging` | Род упаковки, число мест, общий вес | — | одно значение |
| `beneficiary` | Выгодоприобретатель | Выгодоприобретатель | одно значение |
| `sum` | Страховая сумма | Страховая сумма | одно значение; `amounts()` — сумма с валютой из соседней ячейки или колонки «Валюта» |
| `transport` | Транспорт | Вид транспорта (и перевозчик) | части через «+», «,», «;», «/» |
| `departure` | Пункт отправления | Маршрут: пункт отправления | пункты маршрута через « - » |
| `transshipment` | Пункт перегрузки | Маршрут: пункт перегрузки | пункты маршрута через « - » |
| `destination` | Пункт назначения | Маршрут: пункт назначения | пункты маршрута через « - » |
| `period` | Период страхования (с … по …) | — | — ; `dates()` — (начало, окончание) |
| `period_start` | — | Период страхования: начало | — ; `dates()` — (начало,) |
| `period_end` | — | Период страхования: окончание | — ; `dates()` — (окончание,) |
| `document` | Товарно-транспортная накладная № … от … | — | номера; `dates()` — все даты |
| `document_number` | — | Номер ТТД | номера через запятую |
| `document_date` | — | Дата ТТД | — ; `dates()` — все даты, год может стоять один раз в конце |
| `carrier` | Перевозчик | (отдельная колонка в некоторых ПСГ, см. вопросы) | одно значение |
| `sealing` | Пломбирование | — | одно значение |
| `other` | Прочие сведения | — | одно значение |

Нормализация, которую делает парсер (без LLM): даты из серийных чисел Excel, `datetime`,
«ДД.ММ.ГГГГ», «ДД.ММ» со списком и годом в конце, «15 сентября 2026 г.»; суммы с пробелами и
запятой; валюта из слов («рублей», «евро», «китайских юаней») в коды ISO 4217. Непрочитанное
значение не угадывается: `dates()` или `amounts()` возвращают пустой кортеж, а `text()` —
исходный текст.

`Shipment.number()`: если в декларации одна перевозка — «200», если больше — «200/N», где N —
№ п/п строки. `Shipment.start()` — дата начала периода страхования этой строки.

## 3. Карточка правила

Файлы — [cards/](../cards/), один файл на поле, имя файла = ключ поля.

```yaml
field: period_end                 # ключ поля
forms:                            # формы, порядок строки и подпись в результате
  psg: {order: 4, title: "Период страхования окончание"}
subject: "Срок действия Полиса"   # колонка «С каким пунктом Ген. полиса сверено»
clause: term                      # ключ пункта в профиле полиса (none — не сверяется)
check: date_range                 # exact | fuzzy | date_range | lte_limit | filled | in_list | conditional | semantic
rule: "…"                         # правило словами; для semantic уходит в промпт
params: {…}                       # параметры типа проверки
if_empty: mismatch                # match | mismatch | skip | review
comments:                         # шаблоны: {reference}, {entry}, {limit}, {policy_start}, {policy_end}
  match: "Входит в срок действия ГП"
  mismatch: "Выходит за срок действия ГП (до {policy_end})"
  review: "Дата окончания не распознана"
status: draft                     # draft | approved
evidence: […]                     # откуда правило: замечания ФСЦ
clarify: […]                      # что уточнить у ФСЦ
```

Общие правила движка (одинаковы для всех карточек):
1. Пустое поле (`Blank` или значение из `blank_words`) → статус из `if_empty`, проверка не
   запускается.
2. **Особые условия клиента.** Перед проверкой движок спрашивает пункт
   `accepted.<ключ поля>`. Если значение поля совпадает с одним из принятых значений
   (нечётко) — «совпадает» со ссылкой на особые условия. Пример: «в соответствии с п.8 ГП»
   в поле `transport` (декл. 263). *Предложено, требует подтверждения ФСЦ.*
3. Если поле состоит из нескольких позиций, итог строки — худший статус:
   не совпадает > требует проверки > совпадает.
4. Пункта нет в профиле (`Absent`) → «требует проверки» с кодом `clause.absent`.
5. Код причины: `<поле>.<исход>`, например `period_end.after_policy_end`, `sum.over_limit`,
   `sum.currency`, `cargo.excluded`, `llm.invalid_json`.

## 4. Профиль полиса

JSON по схеме; извлекается LLM при загрузке пакета полиса, подтверждается экспертом ФСЦ один
раз. Каждый пункт хранится списком редакций.

```json
{
  "number": "…", "issued": "2025-12-22", "insurer": "…",
  "clauses": {
    "term": [
      {"source": "ГП п. 6", "effective": "2025-01-01", "scope": "all",
       "text": "…", "dates": ["2025-01-01", "2026-12-31"]},
      {"source": "ДС 4 п. 1", "effective": "2026-03-01", "scope": "all",
       "text": "…", "dates": ["2025-01-01", "2027-03-31"]}
    ],
    "limit": [
      {"source": "ГП п. 12", "effective": "…", "scope": "all", "amounts": [{"value": "900000000", "currency": "RUB"}]},
      {"source": "ДС 4", "effective": "…", "scope": ["99"], "amounts": [{"value": "1154000000", "currency": "RUB"}]}
    ]
  },
  "conditions": ["…особые условия текстом для результата…"]
}
```

`scope` — `"all"` или список номеров деклараций, к которым относится ДС. Редакция выбирается
так: из редакций, которые действуют на дату начала перевозки и относятся к её декларации,
берётся последняя по номеру ДС и дате вступления.

Ключи пунктов, на которые ссылаются карточки:

| Ключ | Что содержит |
|---|---|
| `insurer` | наименование страхователя |
| `number` | номер ГП; `dates()` — дата ГП |
| `term` | срок действия: (начало, окончание) |
| `term_extension` | есть, если полис действует до окончания ответственности по партиям, начатым в срок |
| `limit` | лимит на одну перевозку (партию) |
| `object` | объект страхования (п. 5) |
| `exclusions_cargo` | исключённые грузы |
| `transport` | разрешённые виды транспорта (п. 8) |
| `territory` | территория и маршруты (п. 9) |
| `exclusions_territory` | исключённые территории |
| `beneficiary` | условия о выгодоприобретателе (п. 3) |
| `carriers` | перечень перевозчиков |
| `carrier_risk` | есть, если в ГП включён риск, требующий сверки с перечнем перевозчиков (например 3.4.28) |
| `accepted.<поле>` | значения поля, допустимые по особым условиям клиента |
