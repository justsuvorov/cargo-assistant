# Эталон (черновик)

Эталон — ожидаемые статусы результата по строкам «поле × перевозка». Статус: **черновик**,
его подтверждает пользователь. Файлы обезличены: названий клиентов, ИНН, номеров ГП, адресов и
ФИО здесь нет; комментарии MVP не копируются, замечания ФСЦ попадают только в
`docs/eval/questions.md` и только через маску.

## Файлы

| Файл | Что в нём |
|---|---|
| `cases/<декларация>.csv` | эталон: одна строка — одно место результата |
| `manifest.yaml` | версия эталона, журнал изменений, группа полиса и часть (dev / holdout) каждой декларации |
| `rulings.yaml` | вход сборки чернового эталона: форма каждой декларации, подписи без одного ключа, испорченные строки MVP, решения по замечаниям ФСЦ |
| `../../docs/eval/questions.md` | строки разметки, которые не вошли в эталон, с причиной и предложением |
| `../../docs/eval/summary.md` | сколько строк размечено, вошло в эталон, ушло в вопросы — по декларациям и полям |

Черновые `cases/`, `questions.md` и `summary.md` собираются командой и руками не правятся:

```
python -m tools.eval gold --source "<папка unpacked с разметкой ФСЦ>"
```

Новые декларации, размеченные экспертом по шаблону, добавляются командой
`python -m tools.eval load <каталог с шаблонами>`, после неё — `python -m tools.eval split`
(подробно — [docs/eval/README.md](../../docs/eval/README.md)).

## Формат `cases/*.csv`

UTF-8, первая строка — заголовок; колонки читаются по имени.

| Колонка | Значение |
|---|---|
| `declaration` | номер декларации: `005`, `35`, `113`; сравнивается по цифрам без ведущих нулей (D-30) |
| `shipment` | строка результата: `97` (одна перевозка) или `113/2` |
| `field` | ключ поля из `docs/contracts.md`, раздел 2 |
| `status` | ожидаемый статус: `match`, `mismatch`, `review` |
| `confidence` | `sure` — входит в расчёт точности; `disputed` — спорная строка, в расчёт не входит, пока её не разрешат. Без колонки все строки `sure` |
| `basis` | основание: `fsc-ok` — ФСЦ «верно», статус MVP; `fsc-note` — статус следует из пояснения ФСЦ; `D-xx` — решение пользователя; `fsc-expert` — ответ эксперта по шаблону разметки |
| `clause` | пункт ГП / ДС, на который ссылается эксперт (обезличен); у черновых строк пусто |
| `reason` | причина «не совпадает» или «требует проверки» словами эксперта (обезличена); у черновых строк пусто |
| `note` | заметка: у черновых строк — короткая заметка eval своими словами (для `fsc-ok` пусто), у строк по шаблону — примечание эксперта |

## `manifest.yaml`

```yaml
version: v1
log:
  - {version: v1, date: "…", change: "что изменено", reason: "почему", confirmed: "кем подтверждено"}
declarations:
  "005": {policy: Полис-1, part: dev}
```

`policy` — порядковая метка группы полиса, а не номер. Декларации одного полиса — в одной
части. Часть уже размеченной декларации не меняется.

## Правило вывода ожидаемого статуса (черновик из разметки ответов MVP)

1. ФСЦ «верно» → статус MVP (`fsc-ok`). Пометка MVP «[ТРЕБУЕТ ПРОВЕРКИ: …]» в комментарии —
   не статус; статус — колонка «Результат проверки».
2. «Некорректно» / «неправильно» / «частично» с пояснением, из которого статус следует
   однозначно, → статус по пояснению (`fsc-note`). Замечание только к комментарию или к
   пометке «доп. проверка» статус MVP не меняет.
3. Решение пользователя (D-xx) важнее отметки ФСЦ.
4. Остальное — «некорректно» без пояснения, противоречивая разметка, нет отметки — в вопросы.
5. Набор полей — по форме декларации (D-14): у ПСГ нет `packaging`, `sealing`, `other`; такие
   строки MVP исключаются. Подпись MVP, которой в форме соответствуют несколько ключей
   (например, «Период страхования» в ПСГ), идёт в вопросы.
6. Строки MVP из `broken` (114/4) в эталон не входят (Ф-19).

Подписи полей MVP сопоставляются ключам по `forms.*.title` карточек `cards/*.yaml`; подпись
другой формы принимается, если её ключ есть в форме декларации («Полное наименование груза»
→ `cargo` в ПСГ).

## Как менять

Ожидаемый статус меняется только с согласия пользователя: правка `rulings.yaml` (черновик) или
файла декларации, пересборка, новая версия и запись в журнале `manifest.yaml`, отчёт
`python -m tools.eval run` до и после.
